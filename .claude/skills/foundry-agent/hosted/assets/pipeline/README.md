# Release pipeline for {{AGENT_NAME}}

Generated release code for a hosted Microsoft Agent Framework agent. Creation never installs a workflow
and never dispatches one; it also provisions no Azure resources and deploys nothing. It only wrote these
files, and nothing in this folder has been run against GitHub, Foundry or Azure.

**Status: BLOCKED.** The lifecycle adapter is `unconfigured`. It cannot create a candidate version that
serves no traffic or identify a promotion boundary, so `agent-deploy.yml` stops at its `check` step
(exit code 3) before any Azure login. Do not describe this pipeline as release-ready until a reviewed
adapter is supplied and exercised in an authorized run.

## Files

| File | Purpose |
|---|---|
| `agent-ci.yml` | Pull request validation only. Read-only token, no Azure login, no secrets or variables. |
| `agent-deploy.yml` | Manual release: candidate, evaluation, gate, promotion, smoke. `workflow_dispatch` only. |
| `hosted_pipeline.py` | Standard-library helper: release gate, identities, `LifecycleAdapter` interface. |
| `release.json` | Confirmed evaluation settings and the unconfigured values that block a release. |

## Lifecycle

Adapted from the reference repository. Each stage of the reference maps as follows.

| Reference | Here |
|---|---|
| Validate definitions on pull request | `agent-ci.yml`: session-manager preflight and `hosted_pipeline.py validate` |
| Deploy a new version, not live until evaluated | `LifecycleAdapter.deploy_candidate`: a candidate that serves no traffic, observed, not trusted |
| Evaluate the new version | `run_evaluation` on the exact candidate; every configured evaluator must report and meet `min_pass_rate` |
| Pin the gateway to the evaluated version | `promote` of the one version that was evaluated and looked up again from the platform |
| Smoke test | `smoke` of the serving target after promotion |
| (none) | Hosted session-manager enablement and a continuity check are required before promotion |
| (none) | Router agents also need candidate-scoped route evidence |

Not copied from the reference: the prompt-agent deployment call, the gateway (APIM) registration and
its documentation publishing, the definition hash, the rule that skips evaluation for a version approved
earlier, and its push-to-main deployment trigger. None of the first three are generated by default.

The gate blocks promotion when: the evaluation is failed, canceled, timed out, empty or 0 of 0; any
evaluator is missing or below its threshold; the evaluated version, candidate, artifact, dataset,
source, run, criteria or evaluator set does not match this release; the session manager is not
confirmed enabled or the continuity check did not pass; or a router lacks candidate-scoped route
evidence. A failed evaluation leaves the previous serving version unchanged. If the smoke test fails
after promotion the run fails and the report says whether the previous version was restored
(`ROLLED_BACK`) or a person must act (`REMEDIATION_REQUIRED`). It is never reported as success.

Changing the dataset, evaluators, threshold, judge model, tool schema, any pipeline file or the
deployable source changes the identities, so earlier evidence cannot be reused.

## Installation (future, Phase 2)

Only an explicit request to the deploy skill installs or selects these workflows and dispatches them.
Until then:

1. Copy `agent-ci.yml` and `agent-deploy.yml` to the repository's `.github/workflows/`. Creation never
   does this, and the files in this folder are not active workflows.
2. Create a GitHub environment per target (for example `dev`, `demo`) with required reviewers.
3. Run **Actions, agent-deploy-{{AGENT_NAME}}, Run workflow** with the agent name and the environment.
   Concurrency allows one run per agent and environment at a time and never cancels a running release.

## Variables

Set per GitHub environment (Settings, Environments, Variables). The workflow has no literal values.

| Variable | Meaning |
|---|---|
| `AZURE_CLIENT_ID` | Client id of the identity used for OIDC login |
| `AZURE_TENANT_ID` | Directory the identity belongs to |
| `AZURE_SUBSCRIPTION_ID` | Subscription used by the adapter |
| `FOUNDRY_PROJECT_ENDPOINT` | Foundry project the agent is released to |
| `AZURE_AI_MODEL_DEPLOYMENT_NAME` | Model deployment used by the agent and the evaluators |

A missing value stops the release with a configuration error. Nothing here is defaulted.

## OIDC identity and RBAC

Use a user-assigned managed identity or app registration with a federated credential whose subject is
the repository and the GitHub environment (`repo:<owner>/<repo>:environment:<environment>`), so only
that environment can obtain a token. No client secrets are used. The role assignments the adapter needs
(for example Foundry project access for agents and evaluations) depend on the adapter you supply;
grant the minimum and record them with the adapter.

## Approvals

The `environment` is the approval point: configure required reviewers and, where appropriate, a branch
restriction. A manually dispatched workflow can still be run by anyone allowed to dispatch workflows in
the repository.

## Blocked and unconfigured steps

- **Lifecycle adapter** is `unconfigured`. Supply a `LifecycleAdapter` that creates a non-serving
  candidate and promotes one named version, register it in `hosted_pipeline.ADAPTERS`, and set
  `adapter` in `release.json`. If the platform cannot do both, leave this blocked.
- **Evaluation settings** in `release.json` (judge model, evaluators, threshold, approved dataset) are
  listed under `blockers` until the owner confirms them. The reference's example thresholds are not a
  standard to copy.
- **Session manager**: enablement must be confirmed on the candidate and a hosted continuity check must
  pass before promotion. A local preflight only checks the source.
- **Router agents**: blocked until an adapter returns route evidence scoped to the candidate version.
  A local routing check cannot stand in.
- **Dataset**: proposed cases are not release evidence. Approve them before a real release.
